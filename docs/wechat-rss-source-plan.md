# 微信公众号 / RSS 信号源扩量方案

> 目的：给事件引擎扩"信息流量"。RSS 管道已就绪（`engine/sources/rss.py`），
> 现在缺的是**对口的号**。本文 = 中转方案对比 + 选号模板，给 Nicole/销售拍清单用。

## 0. 现状结论（2026-06-29 实测）

- ✅ **管道已通**：`engine/sources/rss.py` 通吃任意 RSS 落盘文件（`data/rss/*.json`），按
  阀型/工况词过滤 → 产出 `source_type=news` 事件。零重复抓取（吃 `fetch_rss.py` 的产出）、
  离线可跑、微信只是清单里的几条 feed。
- ❌ **现有 28 个 feed 喂进去 = 0 事件**：它们是为"热度仪表盘"选的**宏观/趋势号**
  （半导体产业纵横、氢能创业、光模块、AI），不发项目/Capex 消息，没一条命中工况词，
  也确实不该命中。
- 🎯 **真正的杠杆 = 选对号**：发"扩产/新建/投产/招标/中标/拿地"的
  **制药装备 / 化工园区招商 / 地方发改 / 流体设备行业号**。号一加进 `rss_sources.json`，
  `fetch_rss` 抓 → `data/rss` 落盘 → 引擎自动吃，**引擎侧零改动**。

> 注：现有 RSS 里的条目 url 已多是 `mp.weixin.qq.com`——微信中转**已在用**，问题不在通道，在选号。

## 1. 微信中转方案对比

公众号没有公开官方读 API，抓别人的号都是灰色+脆弱。按"可靠 × 运维成本"排：

| 方案 | 原理 | 可靠性 | 成本/运维 | 适配本项目 |
|---|---|---|---|---|
| **RSSHub 自建** | 开源聚合器，`/wechat` 等路由把号转 RSS | 中（路由常随源失效） | 自建一个服务（docker），免费但要维护 | 🥈 输出即 RSS，直插现管道 |
| **wechat2rss / werss 等中转** | 专做微信→RSS 的服务（自建或托管） | 中-高 | 自建要养登录态；托管多收费 | 🥇 专做微信，最省心 |
| **mp 后台接口** | 自己注册公众号，用登录 cookie+token 调 `searchbiz`/`appmsg` 列别人文章 | 高 | 要注册号 + 定期刷 cookie + 限频极狠（爬几十次封几小时） | 🥉 最稳但运维重，需在 CI 养号 |
| **新榜 / 西瓜数据 付费 API** | 商业舆情平台 | 高 | 花钱 | 预算够再说 |

**推荐路径**：先用 **wechat2rss / RSSHub 自建**（输出 RSS，零改引擎），覆盖不够/不稳再上 mp-token 或付费。
**所有方案都该在 CI/服务器跑，不在本机**（同招标/环评的教训：无头开发机是最差战场）。

## 3. 选定后怎么接（零引擎改动）

1. 把号配进中转服务，拿到每个号的 RSS url。
2. 加进 `rss_sources.json` 的某个 vertical（或新建一个 `pharma_capex` / `park_news` vertical）。
3. CI 里 `fetch_rss.py` 先跑 → 落 `data/rss/*.json`，`engine.run` 后跑 → `rss.fetch` 自动吃。
   **CI 顺序：fetch_rss 在前，engine 在后。**
4. 验证：`python3 -c "from engine import conditions; from engine.sources import rss; print(len(rss.fetch(conditions.load_conditions())))"`

## 4. 配套提醒

- **量上来 = 噪声上来**：news 是软信号（不点名业主常 `unresolved`、`source_boost` 最低 0.3），
  务必配 去重 + 新鲜度（见 ROADMAP / 上一轮"源加固"批次），否则信箱会被新闻刷屏。
- **ToS 灰色**：微信抓取违反平台条款，内部研判工具自用风险可控，别外发/商用分发原文。
